03_TECH_STACK_SETUP
====================

TOOLCHAIN (verified working versions - do not blindly upgrade)
--------------------------------------------------------------
  Node.js v24.15.0, npm 11.12.1 (package-lock.json pinned)
  Next.js 16.4.3 (App Router, src/ directory, Turbopack)
  React 19.3.0, TypeScript 5.9.x
  Tailwind CSS v4 (@tailwindcss/turbopack, CSS-first config)
  Zod 4.6.7 (AI response + boundary validation)
  All animation is CSS keyframes (the motion dependency was removed).
  Vitest 5.0.5, Playwright 1.64.1, cross-env

FIRST RUN
---------
  git clone https://github.com/Avani376/jallekha.git
  cd jallekha
  npm install
  npm run dev            # http://localhost:3000

NPM SCRIPTS
-----------
  npm run dev          development server
  npm run build        production build (server mode, 10 routes)
  npm run build:static static export to out/ (+ prefetch shim, 9 routes)
  npm run start        serve the server-mode build
  npm run lint         eslint - must be 0 errors, 0 warnings
  npm run typecheck    next typegen + tsc --noEmit - must be 0 errors
                       (typegen first: a fresh clone has no generated route
                       types until the first build, and tsc alone would
                       fail on LayoutProps/PageProps)
  npm test             vitest - must be 41/41
  npm run preflight    privacy gate: fails if private paths are tracked
  npm run verify       typecheck + lint + test + build (run before push)

E2E
---
  npx playwright install chromium        (once)
  node tests/e2e/journeys.spec.mjs http://127.0.0.1:3000
  Must report 33/33. It drives the PRODUCTION static build served on the
  given port; build:static first or point it at any server-mode instance.

ENVIRONMENT VARIABLES (none required to run; .env.example lists names)
----------------------------------------------------------------------
  AI_MODE      disabled|live        server-side AI proxy switch (off)
  ZAI_API_KEY  server-only key      never browser-exposed
  ZAI_MODEL / ZAI_BASE_URL          provider config for the proxy
  The in-app AI (Settings) does not need these: it uses the operator's own
  key from the browser. Never put real values in any committed file.

STORAGE
-------
  localStorage keys (per browser):
    jallekha.workspace.v1   demo workspace
    jallekha.real.v1        real ("My data") workspace
    jallekha.data-mode      demo | real
    jallekha.reduce-motion  0 | 1
    jallekha.ai.v1          AI settings (operator's own key)
  Clearing these = fresh state. "Reset demo" reseeds; "Delete all my
  records" (Settings, real mode) requires typing DELETE.

BUILDS
------
  Server build (default): standard Next build; deployable to any Node host
  or Vercel. Needed if you later enable server routes (e.g. the AI proxy
  described in docs/AI.md).
  Static export: NEXT_STATIC=1 disables cacheComponents/PPR and emits out/.
  The app is 100% client-side in this mode (no API routes may exist).
  scripts/fix-static-prefetch.mjs then flattens the router prefetch files
  (a Next 16.4.3 export quirk) - do not remove it.

DEPLOY (static host)
--------------------
  1. npm run build:static
  2. Stage out/ with any static file server that serves index.html for "/"
     and falls back for extensionless routes. The local convention lives in
     a stage/ directory next to the repo checkout (see the owner).
  3. Verify: open "/", "/demo", "/workspace/dashboard", run one signature
     journey, check the console is clean.
  The public demo runs this way; the owner manages the hosting account.

DEPLOY (Vercel, recommended for server features)
------------------------------------------------
  Import the repo, framework auto-detects Next.js, no custom settings
  needed. Server routes become available (AI proxy, future shared
  backend). Static export is not used in this mode.

FOLDERS
-------
  src/app/        routes: / (landing), /demo, /workspace/* (client)
  src/domain/     pure TypeScript engine + types + import parsing
  src/data/       adapters, seed, store (useSyncExternalStore)
  src/lib/        datetime + analytics + ai (settings/client/context)
  src/components/ ui kit, charts, mascot, equation card, AI panels
  public/brand/   sevaforge-mark.png (team mark used by the landing stage)
  fixtures/synthetic/  signature scenarios + expected outcomes
  tests/domain/   Vitest suites        tests/e2e/  Playwright journeys
  scripts/        fix-static-prefetch.mjs, preflight-check.mjs
  docs/           ARCHITECTURE.md, VALIDATION.md, AI.md
